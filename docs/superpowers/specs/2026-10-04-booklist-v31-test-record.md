# Z-lib Booklist Enhancer v3.1 验收记录

日期：2026-10-04。安装产物：`booklist-enhancer.user.js`，版本 `3.1.0-dev`。此文区分 Node 自动化验证、静态代码检查与真实浏览器验收；前者不能代替后者。

## 已运行的自动化验证

在当前仓库运行 `node --test`、`node --check booklist-enhancer.user.js` 与 `git diff --check`。现有 Node 测试覆盖：旧设置兼容、十语言翻译键、全局设置与逐项配置互斥、文本提交、统一筛选、下载等待、Show more 批量判断和 5＋5 秒倒计时、累计点击/失败文案、手动点击卡住判定、迟到书卡撤销卡住、重置只处理标准禁用属性、CSS 仍禁止点击时不宣称恢复、批量开页门控与双确认、收藏入口仍禁用。最终测试数量及结果以实施完成时的命令输出为准。

本地夹具 `tests/fixture.html` 提供正常加载、一次卡住、CSS-only 禁用、下载映射迟到、分批新增和书卡替换场景。夹具中的 `GM_openInTab` 只增加本地计数，不会实际打开书页；不得用真实站点测试批量开页或收藏。

本轮在 Codex 内置浏览器打开本地夹具，目视确认面板和书卡排列，逐项展开格式配置、下载配置、全局设置：前一个区域会收起，下载开关未就绪时配置仍能打开。未授权点击「打开当前视图的所有图书页面」只显示一个「关闭」按钮的信息弹窗。使用夹具的「下次卡住」触发原站 Show more 后，原站按钮与五连入口禁用；10 秒后重置入口启用；手动重置后原站与五连入口恢复，重置入口再次禁用，并显示重复加载风险提示。此结果只证明**本地夹具**路径，不证明真实 Z-Library 的内部加载锁可恢复。

同一夹具中实际点击五连入口后，按钮在运行时显示 `[Running]`，随后完成 5 次原站点击；按钮显示 `[clicked 5 times]`，原站页数估算从约第 1 页变成约第 6 页，批量开页按钮在任务结束后恢复可点击。浏览器错误日志为空。

随后让五连下一次点击卡住：任务最终停止，按钮累计显示 6 次点击、1 次失败，原站按钮仍禁用而手动重置入口开放。中间 5～9 秒的倒计时由假时钟 Node 测试覆盖；本次浏览器采样没有截获该短暂画面，不记为真实 UI 验收通过。浏览器错误日志仍为空。

将内置浏览器视口临时设为 375×800 后，面板改为页面内流式定位并可独立滚动，主控件未见水平裁切；随后已恢复默认视口。200% 缩放、系统夜间模式和强制高对比度尚未实测。

## 真实站点边界

此前在已登录 `1lib.sk` 样本中只读确认过原站按钮是 `div.page-load-more`，包含 `.content` 和 `onclick="loadMoreBooks(this)"`；未记录加载中的禁用属性或内部加载锁。此次尝试重新打开同一书单，两次浏览器绑定超时，Web 打开返回不可访问，命令行 HTTPS 连接失败。因此原站卡住状态和按钮恢复机制**未验证**。本版重置只恢复可确认的 `disabled` / `aria-disabled`，不会猜测类名、调用站点私有方法或自动重发请求。若站点实际通过别的方式锁定按钮，重置入口可能始终不可用。
